1. CAMERA STAYS ON AFTER RECORDING STOPS
================================================================================

STATUS: ✅ FIXED

PROBLEM:
- When users finish the communication assessment and click "Finish Assessment"
- Video recording stops but camera light remains on
- Console shows "Video recording stopped" but camera doesn't turn off

ROOT CAUSE:
Location: src/contexts/VideoRecordingContext.tsx (Lines 117-137)

The stopRecording() function had TWO code paths:
1. Active recorder path (lines 140-160) - Stops camera tracks ✅
2. Inactive recorder path (lines 117-137) - Does NOT stop camera tracks ❌

When stopRecording() was called and the MediaRecorder was already inactive
(e.g., called twice quickly, or auto-stopped), the inactive path executed
which only created a video blob but never stopped the camera/microphone tracks.

FIX APPLIED:
Location: src/contexts/VideoRecordingContext.tsx (Lines 135-144)

Added track stopping code to the inactive branch:
```
// Stop all tracks even if recorder is inactive
if (streamRef.current) {
  console.log('🔴 Stopping camera/microphone tracks...');
  streamRef.current.getTracks().forEach(track => {
    console.log(`🛑 Stopping track: ${track.kind} (${track.label})`);
    track.stop();
  });
  streamRef.current = null;
  console.log('✅ All tracks stopped');
}
```

RESULT:
- Camera tracks now stop in BOTH code paths
- Added detailed logging to track which tracks are being stopped
- Camera light should turn off immediately when assessment completes

   const audioEvalResponse = await evaluateAudio({

3. LOGOUT FUNCTIONALITY NOT WORKING
================================================================================

STATUS: ❌ NOT FIXED - REQUIRES BACKEND DEVELOPER ATTENTION

PROBLEM:
- User clicks logout button in Sidebar
- Nothing happens - no redirect, no error message, no success message
- No feedback to user at all

ROOT CAUSE:
Location: src/api/authApi.ts (Lines 53-58)

Multiple issues in the signOut() function:

ISSUE 1: Silent Error Swallowing (Line 54)
```
await httpClient.post("/auth/signout").catch(() => {});
```
- The .catch(() => {}) silently catches and ignores ALL errors
- If backend returns 404, 401, 500, or any error, it's invisible
- No logging, no toast notification, nothing

ISSUE 2: Hard Redirect Blocks UI Feedback (Line 57)
```
window.location.href = "/";
```
- Causes immediate hard page redirect after API call
- Code in Sidebar.tsx (lines 150-153) that shows success toast NEVER executes
- Page redirects before toast can display
- Users get no feedback about logout success/failure

ISSUE 3: Potentially Wrong Endpoint (Line 54)
```
await httpClient.post("/auth/signout")
```
- Calls /auth/signout
- Admin logout (which works) uses /auth/logout
- Backend might expect /auth/logout instead

ISSUE 4: No Error Logging
- When API call fails, no console.error or logger statement
- Impossible to debug what's happening

COMPARISON WITH WORKING ADMIN LOGOUT:
Location: src/api/adminAuthApi.ts (Lines 269-280)

```
export const adminLogout = async (): Promise<void> => {
  try {
    await httpClient.post('/admin/auth/logout');  // ✅ Proper endpoint
  } catch (error) {
    logger.error('Error logging out admin:', error);  // ✅ Logs errors
  } finally {
    if (typeof window !== 'undefined') {
      window.location.href = '/admin/login';  // ✅ Redirect in finally
    }
  }
};
```

RECOMMENDED FIX (for backend developer):
1. Remove .catch(() => {}) - let errors propagate to Sidebar component
2. Add proper error logging with logger.error() or console.error()
3. Remove window.location.href redirect - let Sidebar handle navigation
4. Verify correct backend endpoint: /auth/logout vs /auth/signout
5. Use try-catch-finally pattern like adminLogout

The Sidebar component already has proper error handling (lines 154-158)
but it never executes because signOut redirects the page before returning.

FILES AFFECTED:
- src/api/authApi.ts (Lines 53-58) - signOut function needs refactoring
- src/components/layout/Sidebar.tsx (Lines 140-159) - handleLogout (working correctly)

5. BUILD CONFIGURATION FIXES APPLIED
================================================================================

STATUS: ✅ FIXED

ISSUE A: UUID Module Resolution Error
PROBLEM:
- Build error: "ENOENT: no such file or directory, open uuid/dist/esm-node/index.js"
- Next.js 15.5.4 directory structure mismatch with uuid v13.0.0

FIX APPLIED:
Location: next.config.ts (Lines 44-48)
```
config.resolve.alias = {
  ...config.resolve.alias,
  'uuid': require.resolve('uuid'),
};
```

ISSUE B: Node: Protocol Import Error
PROBLEM:
- "UnhandledSchemeError: Reading from 'node:crypto' is not handled by plugins"
- Webpack cannot handle node: protocol imports

FIX APPLIED:
Location: next.config.ts (Lines 35-42)
```
config.plugins.push(
  new webpack.NormalModuleReplacementPlugin(
    /^node:/,
    (resource: any) => {
      resource.request = resource.request.replace(/^node:/, '');
    }
  )
);
```

ISSUE C: Next.js 15 Viewport Metadata Warning
PROBLEM:
- Warning: "Unsupported metadata viewport is configured in metadata export"
- In Next.js 15, viewport must be separate export, not in metadata object

FIX APPLIED:
Location: src/app/layout.tsx (Line 11)
```
// viewport: "width=device-width, initial-scale=1, maximum-scale=1",
```
Commented out deprecated viewport configuration

7. RESUME ID AUTHENTICATION AND STORAGE REFACTOR
================================================================================

STATUS: ✅ COMPLETED

PROBLEM:
- EmptyState component was checking localStorage for auth tokens
- This is incompatible with httpOnly cookie authentication
- Resume ID was stored in localStorage (security concern)
- Users were seeing "Please sign in to create a resume" error even when authenticated

ROOT CAUSE:
Multiple locations were using localStorage for authentication and resume ID:
1. EmptyState.tsx - Checking localStorage for auth tokens (lines 886-892 in old code)
2. TemplatesTab.tsx - Getting resume ID from localStorage
3. ResumeContext - Using localStorage to get/set resume ID

ARCHITECTURAL DECISION:
Implemented URL parameter approach for resume ID management:
- Authentication: httpOnly cookies (browser-managed, secure)
- Resume ID: URL parameters via Next.js dynamic routes
- No localStorage usage for sensitive data

IMPLEMENTATION:

STEP 1: Fixed EmptyState Authentication (Line 21-88)
Location: src/app/(resume)/builder/start/_components/EmptyState.tsx
- Removed localStorage token checks
- Let backend handle authentication via httpOnly cookies

- Navigate with resume ID in URL: router.push(`/builder/creation/${resume.id}`)

STEP 2: Created Dynamic Route

- Accepts resumeId from URL params via Next.js App Router
- Passes resumeId as prop to all child components
