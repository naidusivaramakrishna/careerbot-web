2. CURRENT ARCHITECTURE (WHAT EXISTS TODAY)
================================================================================

The endpoint POST /api/v1/english-assessment/generate-test generates a complete
English assessment test with 7 sections and 44 total questions.

Sections Generated:
+-----------------------------+--------+------------------------------------------+
| Section                     | Type   | What Student Does                        |
+-----------------------------+--------+------------------------------------------+
| see_and_repeat              | List/8 | Read aloud sentences shown on screen     |
| listen_and_repeat           | List/8 | Repeat what they hear                    |
| jumbled_sentence            | List/8 | Arrange shuffled words into sentences    |
| sentence_completion         | List/8 | Fill in the blank (____) in a sentence   |
| listen_and_correct          | List/8 | Find and fix grammar errors              |
| story_listen_facts          | Object | Listen to story, answer 3 fact questions |
| describe_situation          | Object | Describe a given scenario out loud       |
+-----------------------------+--------+------------------------------------------+
Total: 44 questions (8 x 5 list sections + 3 story questions + 1 describe)

All 7 sections are generated IN PARALLEL via asyncio.gather(), each making
1 LLM call to Azure OpenAI. In theory, total time = slowest section (2-5s).
In practice: 12-90 seconds due to 7 compounding problems.

Current Performance:
  Easy:   12-15s
  Medium: 25-30s
  Hard:   70-90s (frequently FAILS)

Target Performance:
  Easy:   2-4s
  Medium: 3-5s
  Hard:   4-6s

5. CHALLENGE 1: CACHE FIX CREATES A CHEATING DISASTER

The FIX B code (from V2.2 patch):

```python
def _build_cache_key(input_list: list) -> str:
    cache_parts = []
    for req in input_list:
        dnr = req.get("do_not_repeat_list") or []
        if isinstance(dnr, list) and len(dnr) > 50:
            dnr = sorted(dnr)[-50:]
        cache_parts.append({
            "difficulty": req.get("difficulty", "").lower(),
            "do_not_repeat_list": dnr,
        })
    return json.dumps(cache_parts, sort_keys=True)
```

PROBLEM: By removing email_id from the cache key, EVERY student requesting "easy"
with empty do_not_repeat_list gets THE EXACT SAME 44 questions.

In a college computer lab with 60 students starting the test together:

  - Students 2-60 start within next 30 seconds --> cache HIT --> same 44 questions
  - Student 1 WhatsApps answers to the group --> everyone copies

In a university with 2,000 students during placement week:
  - All "easy" tests are identical
  - All "medium" tests are identical
  - Screenshots spread across hostels in minutes

This is not a bug -- it's a PRODUCT KILLER for colleges.

SCENARIO WALKTHROUGH:

6. CHALLENGE 2: CONCURRENT LOAD DESTROYS AZURE LIMITS
================================================================================

Current code (batch_processor.py:226-227):
```python
tasks = [process_single_request(idx, req) for idx, req in enumerate(requests)]
results = await asyncio.gather(*tasks, return_exceptions=False)
```

Each request triggers 7 parallel LLM calls. In a college scenario:

+-------------------+-----------+-----------------------+------------------+------------------+
| Scenario          | Students  | Concurrent LLM Calls  | Azure RPM Limit  | Result           |
+-------------------+-----------+-----------------------+------------------+------------------+
| Single class      | 60        | 60 x 7 = 420          | 100-300 RPM      | 429 errors       |
| Placement drive   | 500       | 500 x 7 = 3,500       | 100-300 RPM      | MELTDOWN         |
| University exam   | 2,000     | 2,000 x 7 = 14,000    | 100-300 RPM      | IMPOSSIBLE       |
+-------------------+-----------+-----------------------+------------------+------------------+

Even with Semaphore(3) per request, 500 concurrent users = 500 requests x 3 =
1,500 concurrent LLM calls. Still way over Azure limits.

WHAT HAPPENS IN PRACTICE:
  - First 15-40 students: Tests generated successfully (within RPM limit)
  - Students 41+: Azure returns 429 (Too Many Requests)
  - 429 triggers retry logic --> more LLM calls --> MORE 429s --> retry storm
  - Eventually: mass timeout, half the class gets "Test generation failed"
  - Professor's reaction: "This product doesn't work"

AZURE OPENAI RATE LIMITS (typical deployment):
  - Tokens per minute (TPM): 60,000-240,000
  - Requests per minute (RPM): 100-360
  - Each section call: ~500-1500 tokens
  - 7 sections x 500 tokens = 3,500 tokens per student
  - 60 students = 210,000 tokens --> may exceed TPM limit too

  - 7 LLM calls x ~500 input tokens x ~300 output tokens

  - Per section: (500 x $0.03 + 300 x $0.06) / 1000 = $0.033
  - 7 sections: $0.033 x 7 = $0.231 per test (worst case with GPT-4)
  - With GPT-3.5-turbo: ~$0.01-0.03 per test (much cheaper)
  - With retries: multiply by 1.3x average

8. CHALLENGE 4: QUESTION POOL EXHAUSTION
================================================================================

Current code (test_generator.py:654-660):
```python
if not shared_dedup_set:
    cached = _get_cached_section(section_type, difficulty)
```

The do_not_repeat_list grows with every test a student takes.

EXHAUSTION TIMELINE:
  - Test 1: do_not_repeat_list = [] (empty) --> LLM generates freely
  - Test 2: do_not_repeat_list = [44 questions] --> LLM avoids 44
  - Test 3: do_not_repeat_list = [88 questions] --> LLM avoids 88
  - Test 4: do_not_repeat_list = [132 questions] --> LLM struggles
  - Test 5: do_not_repeat_list = [176 questions] --> LLM starts repeating

WHAT HAPPENS:
  - By test 3-4: LLM has seen 132+ questions to avoid
  - The dedup list is INJECTED INTO THE PROMPT (more tokens = slower + costly)
  - Prompt grows: 200 base + 132 x ~10 words = 1,520 extra tokens
  - LLM struggles to generate truly unique questions
  - Quality degrades: trivial variations like:
    "The cat sat on the mat" vs "The dog sat on the rug"
  - Eventually the LLM can't avoid all previous questions
  - Dedup check fails --> retry --> more LLM calls --> timeout

FOR COLLEGES (5 mock tests per semester per student):
  - 5 tests x 44 questions = 220 questions to avoid
  - 220 x ~10 words = 2,200 extra tokens in every prompt
  - Prompt cost doubles, generation quality drops significantly
  - Some sections may fail entirely after test 4-5

```python
async def generate_test_from_pool(
    difficulty: str,
    tenant_id: str,
    do_not_repeat_ids: set
) -> dict:
    """Pick 8 random questions per section from pre-generated pool."""
    sections = {}

    for section_type in SECTION_TYPES:
        # Query: same section + difficulty + not used before + active
        questions = await db.question_pool.aggregate([
            {"$match": {
                "section_type": section_type,
                "difficulty": difficulty,
                "tenant_id": tenant_id,
                "active": True,
                "_id": {"$nin": list(do_not_repeat_ids)}
            }},
            {"$sample": {"size": 8}}  # Random 8 from pool
        ]).to_list(8)

        if len(questions) < 8:
            # Pool running low - log warning, trigger background refill
            logger.warning(f"Pool low for {section_type}:{difficulty} - only {len(questions)}")
            # Pad with any available questions (relaxed uniqueness)
            remaining = await db.question_pool.aggregate([
                {"$match": {
                    "section_type": section_type,
                    "difficulty": difficulty,
                    "active": True
                }},
                {"$sample": {"size": 8 - len(questions)}}
            ]).to_list(8 - len(questions))
            questions.extend(remaining)

        sections[section_type] = questions

    return {"sections": sections}
```

```python
async def assign_test_variant(
    student_id: str,
    difficulty: str,
    tenant_id: str
) -> dict:
    """Assign a random variant, ensuring no two adjacent students get same one."""

    # Get recently used variants in this session (last 30 min)
    thirty_min_ago = datetime.utcnow() - timedelta(minutes=30)
    recent = await db.test_assignments.distinct("variant_id", {
        "tenant_id": tenant_id,
        "assigned_at": {"$gte": thirty_min_ago}
    })

    # Pick variant NOT recently used (if possible)
    variant = await db.variant_pool.aggregate([
        {"$match": {
            "difficulty": difficulty,
            "tenant_id": tenant_id,
            "variant_id": {"$nin": recent[-10:]}  # Avoid last 10 used
        }},
        {"$sample": {"size": 1}}
    ]).to_list(1)

    if not variant:
        # All variants recently used, pick any
        variant = await db.variant_pool.aggregate([
            {"$match": {"difficulty": difficulty, "tenant_id": tenant_id}},
            {"$sample": {"size": 1}}
        ]).to_list(1)

    # Record assignment
    await db.test_assignments.insert_one({
        "student_id": student_id,
        "variant_id": variant[0]["variant_id"],
        "tenant_id": tenant_id,
        "assigned_at": datetime.utcnow()
    })

    # Increment usage counter
    await db.variant_pool.update_one(
        {"variant_id": variant[0]["variant_id"]},
        {"$inc": {"usage_count": 1}}
    )

    return variant[0]["sections"]
```

ANTI-CHEATING MATH:
  - 50 variants per difficulty
  - Class of 60 students
  - Maximum students with same variant: 60/50 = 1-2 (statistically)
  - With recent-avoidance logic: most students get unique variants
  - Even if 2 students get same variant, they're sitting far apart
  - WhatsApp sharing is useless (each student has different questions)

================================================================================

DECISION FLOW:
```
Student requests test
       |
       v
  Pool has enough questions for this section+difficulty?
       |
       +-- YES (pool_count >= 8)
       |    |
       |    v
       |   Pick 8 random from pool (instant, free)
       |    |
       |    +-- Pool running low? (pool_count < 20)
       |         |
       |         v
       |        Background task: refill pool via LLM
       |
       +-- NO (pool empty or insufficient)
            |
            v
           Azure OpenAI available?
            |
            +-- YES: Generate via LLM (real-time, paid)
            |         Add generated questions to pool for future
            |
            +-- NO (Azure down):
                 |
                 v
                Return error: "Test generation temporarily unavailable"
                (This should NEVER happen if pool is maintained)
```

HYBRID CODE:
```python
POOL_MINIMUM = 20  # Refill when pool drops below this

async def get_section_questions(
    section_type: str,
    difficulty: str,
    exclude_ids: set,
    tenant_id: str
) -> list:
    """Get questions from pool first, LLM fallback if pool empty."""

    # Try pool first
    pool_count = await db.question_pool.count_documents({
        "section_type": section_type,
        "difficulty": difficulty,
        "tenant_id": tenant_id,
        "active": True,
        "_id": {"$nin": list(exclude_ids)}
    })

    if pool_count >= 8:
        # POOL MODE: instant, free
        questions = await db.question_pool.aggregate([
            {"$match": {
                "section_type": section_type,
                "difficulty": difficulty,
                "tenant_id": tenant_id,
                "active": True,
                "_id": {"$nin": list(exclude_ids)}
            }},
            {"$sample": {"size": 8}}
        ]).to_list(8)

        # Background: refill if running low
        if pool_count < POOL_MINIMUM:
            asyncio.create_task(
                _refill_pool(section_type, difficulty, tenant_id)
            )

        return questions

    # FALLBACK: LLM generation (only when pool empty)
    logger.warning(f"Pool empty for {section_type}:{difficulty}, falling back to LLM")
    questions = await generate_section_content(section_type, difficulty)

    # Add generated questions to pool for future use
    for q in questions:
        await db.question_pool.insert_one({
            "section_type": section_type,
            "difficulty": difficulty,
            "tenant_id": tenant_id,
            "active": True,
            "quality_score": 0.0,  # Not yet scored
            **q
        })

    return questions
```

BENEFITS:
  - 99% of requests served from pool (instant, free)
  - 1% of requests fall back to LLM (when pool depleted)
  - New questions added to pool automatically
  - Azure outage has zero impact (pool always available)
  - Gradual, automatic pool growth

POOL REFRESH CODE:
```python
async def refresh_question_pool(tenant_id: str):
    """Generate new questions to maintain pool size per tenant."""

    TARGET_POOL_SIZE = 200  # Per section_type per difficulty

    for section_type in SECTION_TYPES:
        for difficulty in ["easy", "medium", "hard"]:
            # Check current pool size
            current_count = await db.question_pool.count_documents({
                "section_type": section_type,
                "difficulty": difficulty,
                "tenant_id": tenant_id,
                "active": True
            })

            needed = max(0, TARGET_POOL_SIZE - current_count)

            if needed > 0:
                logger.info(
                    f"Refilling pool: {section_type}:{difficulty} for {tenant_id} "
                    f"(current: {current_count}, target: {TARGET_POOL_SIZE}, needed: {needed})"
                )

                # Generate in batches of 8 (one LLM call = 8 questions)
                for batch_num in range(needed // 8 + 1):
                    try:
                        questions = await generate_section_content(
                            section_type, difficulty
                        )

                        # Quality check before adding to pool
                        for q in questions:
                            quality = await _score_question_quality(q, section_type)
                            if quality >= 0.8:  # Only keep good questions
                                await db.question_pool.insert_one({
                                    "section_type": section_type,
                                    "difficulty": difficulty,
                                    "tenant_id": tenant_id,
                                    "quality_score": quality,
                                    "times_used": 0,
                                    "active": True,
                                    "created_at": datetime.utcnow(),
                                    **q
                                })

                        # Rate limit: don't overwhelm Azure
                        await asyncio.sleep(1.0)

                    except Exception as e:
                        logger.error(f"Pool refresh failed for {section_type}:{difficulty}: {e}")
                        continue


async def _score_question_quality(question: dict, section_type: str) -> float:
    """Score question quality (0.0-1.0) using rule-based checks."""
    score = 1.0

    text = question.get("question_text", "")
    expected = question.get("expected_text", "")

    # Check minimum length
    if isinstance(text, str) and len(text.split()) < 3:
        score -= 0.3

    # Check for repeated words
    if isinstance(text, str):
        words = text.lower().split()
        if len(set(words)) < len(words) * 0.5:
            score -= 0.2

    # Check expected_text exists and is meaningful
    if not expected or (isinstance(expected, str) and len(expected.strip()) < 2):
        score -= 0.5

    # Section-specific checks
    if section_type == "sentence_completion":
        if isinstance(text, str) and "____" not in text:
            score -= 0.5

    if section_type == "jumbled_sentence":
        if isinstance(text, list) and len(text) < 3:
            score -= 0.5

    return max(0.0, score)
```

POOL SIZE MATH:
  - 7 sections x 3 difficulties x 200 questions = 4,200 questions per tenant
  - Generation cost: ~$20-30 one-time per tenant
  - Refresh cost: ~$5-10/month per tenant (replace used/expired questions)
  - Supports: 4,200 / 8 = 525 unique tests per difficulty before any repeat
  - For 3 tests/student: supports 175 students with zero repeats per difficulty
  - For a college of 500 students: increase pool to 500 per section
    - 7 x 3 x 500 = 10,500 questions per tenant
    - Generation cost: ~$50-75 one-time

22. FIX B CODE REVIEW (Cache Key Normalization)
================================================================================

This is the original FIX B from the V2.2 performance patch. While FIX B correctly
identifies the cache key bug, the Pool Architecture (Solutions 1-6 above) makes
this fix LESS critical because cache is only used during LLM fallback mode.

However, FIX B should STILL be implemented as a quick win until the Pool
Architecture is built.

FILE: src/services/english_assessment/main.py
FUNCTION: generate_tests_with_cache() (line 410)

PROBLEM:
  There are TWO cache layers. The per-section cache (test_generator.py) correctly
  uses key = section_type:difficulty (no email_id). BUT the full-response cache in
  main.py serializes the ENTIRE input_list as the cache key:

  input_list = [{"email_id": "user@x.com", "difficulty": "easy", "do_not_repeat_list": [...]}]
  cache_key = json.dumps(input_list, sort_keys=True)

  Since email_id differs per user, the cache key is unique per user. Two users
  requesting "easy" difficulty with empty dedup lists get DIFFERENT cache keys.
  The full-response cache is effectively USELESS for cross-user sharing.

  This was incorrectly marked as "ChatGPT was wrong" in V2.1. ChatGPT was
  pointing at THIS cache (main.py), not the per-section cache (test_generator.py).
  Both caches exist; only this one has the bug.

CURRENT CODE (main.py, line 427-430):
```python
# Create cache key from input (normalize to handle whitespace variations)
import json
cache_input = json.dumps(input_list, sort_keys=True)
# ^^^ input_list includes email_id --> cache key is user-specific --> useless
cache_key_text = normalize_for_cache(cache_input)
```

SOLUTION:
  Strip email_id from cache key. Only use difficulty + hash of do_not_repeat_list.
  This allows cache sharing across users requesting the same difficulty.

FIXED CODE (main.py, line 427-430):
```python
def _build_cache_key(input_list: list) -> str:
    """Build cache key from difficulty + do_not_repeat_list only (ignore email_id)."""
    import json
    cache_parts = []
    for req in input_list:
        dnr = req.get("do_not_repeat_list") or []
        # Truncate large dedup lists for stable cache keys
        if isinstance(dnr, list) and len(dnr) > 50:
            dnr = sorted(dnr)[-50:]  # Keep last 50 for consistency
        cache_parts.append({
            "difficulty": req.get("difficulty", "").lower(),
            "do_not_repeat_list": dnr,
        })
    return json.dumps(cache_parts, sort_keys=True)

cache_input = _build_cache_key(input_list)
cache_key_text = normalize_for_cache(cache_input)
```

BENEFIT: User A requests "easy" --> cached. User B requests "easy" with same dedup
list --> cache HIT (0s, 0 tokens). Previously: always cache MISS for different users.

IMPORTANT NOTE:
  FIX B alone creates the CHEATING problem described in Challenge 1.
  FIX B should be implemented WITH the Pool Architecture (Solutions 1-6) to get
  the cache benefit WITHOUT the cheating risk. The Pool + Variant system
  ensures different students get different questions, while FIX B ensures the
  LLM fallback cache works across users.

25. CHATGPT'S RECOMMENDED STRATEGY: TWO-TIER CACHE
================================================================================

Source: CACHE_KEY_NORMALIZATION_RISKS_FOR_CLAUDE.txt (Recommended Safer Strategy)

ChatGPT recommended:
  "Cache raw tests by difficulty only. Apply per-user dedup after retrieval.
   Maintain a small spare pool to replace duplicates. Keep a user-specific
   cache only for immediate repeat calls."

Claude verdict: THIS IS THE CORRECT ARCHITECTURE. Adopting fully.

HOW THE TWO-TIER CACHE WORKS:

  Tier 1: GLOBAL CACHE (by difficulty only)
  ==========================================
  - Cache key = difficulty ONLY (e.g., "english_test:easy")
  - Stores GENERIC test with NO user PII
  - Maximum cache sharing (all "easy" requests hit same cache)
  - Dedup list is NOT part of the cache key
  - Result has no email_id, no test_id, no user input

  Tier 2: POST-RETRIEVAL DEDUP (per-user)
  ==========================================
  - After cache hit, check each question against user's dedup list
  - If question was seen before: swap it from the per-section cache pool
  - If no replacement available: keep the question (1 duplicate better than failure)
  - Stamp current user's email_id and generate fresh test_id
  - Store test under current user's account

```python
# ============================================================
# TWO-TIER CACHE (ChatGPT recommended strategy)
# ============================================================

def _difficulty_only_cache_key(input_list: list) -> str:
    """Tier 1 key: ONLY difficulty, maximum cache sharing."""
    difficulties = []
    for req in input_list:
        difficulties.append(req.get("difficulty", "").lower())
    return f"english_test:{'_'.join(sorted(difficulties))}"


def _strip_pii_for_cache(results: list) -> list:
    """Strip all user-specific data before storing in global cache."""
    import copy
    stripped = copy.deepcopy(results)
    for item in stripped:
        if "input" in item:
            item["input"] = {"difficulty": item["input"].get("difficulty")}
        if "result" in item and isinstance(item["result"], dict):
            item["result"].pop("email_id", None)
            item["result"].pop("test_id", None)
    return stripped


def _stamp_user_identity(cached_results: list, input_list: list) -> list:
    """Re-inject current user's PII into cached result."""
    import copy, datetime as dt
    results = copy.deepcopy(cached_results)
    for i, item in enumerate(results):
        current_req = input_list[i] if i < len(input_list) else {}
        current_email = current_req.get("email_id", "anonymous")
        if "result" in item and isinstance(item["result"], dict):
            item["result"]["email_id"] = current_email
            item["result"]["test_id"] = (
                f"test_{current_email}_"
                f"{dt.datetime.now().strftime('%Y%m%d_%H%M%S_%f')}"
            )
        if "input" in item:
            item["input"] = current_req
    return results


def _apply_user_dedup(results: list, input_list: list) -> list:
    """Tier 2: Swap out questions user has seen before."""
    from generators.test_generator import _get_cached_section

    for i, item in enumerate(results):
        if "result" not in item or "error" in item:
            continue

        current_req = input_list[i] if i < len(input_list) else {}
        dnr_raw = current_req.get("do_not_repeat_list") or []

        # Build dedup set
        dedup_set = set()
        for q in dnr_raw:
            if isinstance(q, str):
                dedup_set.add(q.strip().lower())
            elif isinstance(q, dict):
                text = q.get("question_text", "")
                if isinstance(text, str) and text.strip():
                    dedup_set.add(text.strip().lower())

        if not dedup_set:
            continue  # First test, no dedup needed

        # Check each section for repeated questions
        sections = item["result"].get("sections", {})
        difficulty = item["result"].get("meta", {}).get("difficulty", "easy")

        for section_type, section_data in sections.items():
            if not isinstance(section_data, list):
                continue  # story_listen_facts and describe_situation are dicts

            for j, question in enumerate(section_data):
                q_text = question.get("question_text", "")
                if isinstance(q_text, list):
                    # jumbled_sentence: question_text is a list of words
                    q_normalized = " ".join(q_text).strip().lower()
                elif isinstance(q_text, str):
                    q_normalized = q_text.strip().lower()
                else:
                    continue

                if q_normalized in dedup_set:
                    # Try swap from per-section cache pool
                    cached_section = _get_cached_section(section_type, difficulty)
                    if cached_section and isinstance(cached_section, list):
                        for replacement in cached_section:
                            r_text = replacement.get("question_text", "")
                            r_norm = ""
                            if isinstance(r_text, str):
                                r_norm = r_text.strip().lower()
                            elif isinstance(r_text, list):
                                r_norm = " ".join(r_text).strip().lower()
                            if r_norm and r_norm not in dedup_set:
                                section_data[j] = replacement
                                break
                    # If no replacement found, keep the duplicate
                    # (1 duplicate is better than a failed test)

    return results
```
