1. OVERVIEW OF BOTH FEATURES
================================================================================

RESUME BUILDER
--------------
- Purpose  : Create a brand new resume from scratch using guided form inputs
- Input    : Manual data entry (form fields) OR auto-fill from user profile
- AI       : Per-section suggestions, ResumeGPT chat assistant
- Templates: 4 built-in templates
- Scoring  : Completion percentage (how filled in the resume is)
- Storage  : localStorage (survives page refresh)
- Routes   : /builder/start → /builder/start/list → /builder/creation/[resumeId]
- Editor   : Tab-based (Editor tab, Templates tab, Score tab, JobMatch tab)

RESUME ENHANCER
---------------
- Purpose  : Upload an existing resume and improve it using AI
- Input    : PDF or DOCX file upload
- AI       : Full document analysis, ATS scoring, improvement suggestions list
- Templates: 5 built-in templates
- Scoring  : ATS score + keyword match + format score
- Storage  : sessionStorage (cleared when tab closes)
- Routes   : /enhancer → /enhancer/builder
- Editor   : Modal-based (click section → full-screen editor modal opens)

4. STATE MANAGEMENT COMPARISON
================================================================================

BUILDER — ResumeContext
------------------------
Location: src/app/(resume)/builder/creation/_context/ResumeContext.tsx

Data Shape:
  resumeData = {
    resume_id, personalInfo, professionalSummary, education[],
    workExperience[], projects[], skills[], categorizedSkills{},
    certifications[], achievements[], volunteering[], internships[],
    awards[], hobbies[], interests[], languages[], publications[],
    customSections[]      ← UNIQUE TO BUILDER
  }

Methods:
  createResume()
  updateResume(resumeId, data)
  getCompletionPercentage()
  addCustomSection / removeCustomSection
  addCustomField / updateCustomFieldValue / deleteCustomField

Storage: localStorage
  - Key: "resumeData"         → full resume object
  - Key: "selected_template"  → template preference
  - Key: "current_resume_id"  → active resume ID
  - Backup save on beforeunload event


ENHANCER — ResumeContext
------------------------
Location: src/app/(resume)/enhancer/_components/ResumeContext.tsx

Data Shape:
  resumeData = flexible (mapped from parsed PDF)
  sectionOrder: SectionName[]
  enabledSections: SectionName[]
  selectedTemplate: TemplateId
  activeSection: SectionName | null
  highlightedSection: SectionName | null
  editedSections: Set<SectionName>   ← tracks green highlights
  addedFields: Record<string, string[]>  ← tracks newly added fields
  isLoaded: boolean                  ← session restore complete flag

SectionName values:
  "PersonalInfo" | "Summary" | "Experience" | "Skills" | "Education"
  | "Projects" | "Languages" | "Certificates" | "Awards" | "Achievements"
  | "Internships" | "Volunteering" | "Hobbies" | "Interests"
  | "Publications" | "References"

TemplateId values:
  "default" | "apollo" | "atlas" | "terra" | "tempe"
  | "classic_professional" | "nexus" | "pulse" | "zen" | "nova" | "flow"

Storage: sessionStorage
  - Key: "ctx_resumeData"       → resume content
  - Key: "ctx_enabledSections"  → visible sections
  - Key: "ctx_selectedTemplate" → chosen template
  - Key: "enhanced_id"          → backend ID for saves
  - Key: "ats_score"            → ATS breakdown
  - Key: "improvements"         → AI suggestions list
  - Key: "all_improvements"     → full suggestions history


KEY DIFFERENCE:
  Builder uses localStorage  → data persists across browser sessions
  Enhancer uses sessionStorage → data lost when tab closes
  These cannot be unified without changing data persistence strategy

5. API LAYER COMPARISON
================================================================================

BUILDER ENDPOINTS (src/api/resumeApi.ts)
-----------------------------------------
  POST   /resumes/                          Create new resume
  GET    /resumes/                          List all resumes
  GET    /resumes/{id}                      Load resume by ID
  PATCH  /resumes/{id}                      Save full resume
  PATCH  /resumes/{id}/autosave             Incremental auto-save
  DELETE /resumes/{id}                      Delete resume
  GET    /resumes/{id}/download             Export PDF/DOCX
  POST   /resumes/{id}/publish              Publish resume
  GET    /resumes/{id}/score                Get completion score
  POST   /resumes/{id}/calculate-score      Trigger score calculation
  DELETE /resumes/{id}/sections/{section}   Delete a section
  DELETE /resumes/{id}/sections/{section}/items/{itemId}  Delete item

  GET    /templates/                        List templates
  GET    /templates/categories              List categories
  GET    /templates/default                 Get default template
  POST   /templates/{id}/apply             Apply template to resume
  POST   /templates/{id}/set-default       Set user default

ENHANCER ENDPOINTS (src/api/enhancerApi.ts)
--------------------------------------------
  POST   /parser/parse_resume/              Parse uploaded PDF/DOCX
  POST   /resume/enhance                    AI enhance parsed resume
  GET    /resume/enhance/{id}               Load enhanced resume
  PUT    /resume/enhance/{id}               Save user edits
  DELETE /resume/enhance/{id}               Delete enhanced resume
  GET    /resume/enhance/{id}/download      Export PDF/DOCX
  GET    /resume/enhance/{id}/preview       Preview as PDF blob
  POST   /resume/enhance/apply              Apply specific AI suggestion
  GET    /resume/enhance/history/list       Enhancement history list

CONCLUSION:
  Zero overlap in API endpoints.
  Completely separate backend services.
  Cannot share API layer without backend changes.

6. NAVIGATION FLOW COMPARISON
================================================================================

BUILDER FLOW:
  /builder/start
      ↓ (no resumes) → EmptyState component shown
      ↓ (has resumes) → redirect to /builder/start/list
  /builder/start/list
      ↓ user clicks "New Resume" → createResumeWithAuth() API call
      ↓ user clicks existing resume
  /builder/creation/[resumeId]
      ↓ back button → /builder/start/list?refresh={timestamp}
      ↓ download → stays on same page (modal)
      ↓ publish → stays on same page

ENHANCER FLOW:
  /enhancer
      ↓ user drops/selects PDF or DOCX file
      ↓ processResumeEnhancement(file) called
          → Step 1: parseResumeForEnhancer(file) — POST /parser/parse_resume/
          → Step 2: enhanceResume({ resume_id }) — POST /resume/enhance
      ↓ data stored in sessionStorage
  /enhancer/builder
      ↓ user edits sections (modal-based)
      ↓ updateEnhancedResume() called on each save
      ↓ export → ExportModal opens → downloadEnhancedResume()
      ↓ back → returns to /enhancer (loses session data)

PROPOSED UNIFIED FLOW:
  /resume  ← NEW entry page
      ↓ user selects "Build from Scratch"
  /builder/start  (existing flow, unchanged)

      OR

      ↓ user selects "Enhance Existing"
  /enhancer  (existing flow, unchanged)

10. RISK BREAKDOWN
================================================================================

RISK 1: Breaking existing builder navigation
  Likelihood: LOW (if we only add new entry page)
  Impact    : HIGH (users can't create resumes)
  Mitigation: Keep /builder/start route working. New /resume page just adds entry point.

RISK 2: SessionStorage data loss in enhancer
  Likelihood: ALREADY EXISTS (not caused by merge)
  Impact    : MEDIUM (user loses work if tab closes)
  Mitigation: Not related to the merge task. Separate issue.

RISK 3: Context conflicts if merging ResumeContext
  Likelihood: HIGH (if attempted)
  Impact    : CRITICAL (both builder and enhancer break)
  Mitigation: DO NOT merge contexts. Keep them completely separate.

RISK 4: Template ID mismatch
  Likelihood: HIGH (if templates are merged)
  Impact    : MEDIUM (wrong templates shown)
  Mitigation: Defer template unification. Keep separate for now.

RISK 5: TypeScript errors from section editor merge
  Likelihood: HIGH (if editors are merged)
  Impact    : HIGH (build fails, forms break)
  Mitigation: Defer editor consolidation. Out of scope for now.

RISK 6: Sidebar navigation confusion
  Likelihood: LOW
  Impact    : LOW
  Mitigation: Clear labeling on unified entry page.
