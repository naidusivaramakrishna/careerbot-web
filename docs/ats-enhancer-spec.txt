ATS SCAN -> ENHANCER FEATURE SPECIFICATION
==========================================
Project    : CareerBot-Web
Updated    : 2026-03-16
Status     : Frontend Ready | Backend endpoints to verify/implement


==========================================================
1. PRODUCT VISION
==========================================================

Feature         | What it shows                                          | Data source
----------------|--------------------------------------------------------|----------------------------------------
ATS Scan        | ATS score + section breakdown + missing items (issues)  | parse_resume + calculate_ats_score
Enhancer        | Same score + same missing items + enhanced resume        | resume/enhance (uses same resume_id
                | sections + editing + export                             | + ats_id)

Both pages share the same underlying parsed resume data.
The score and missing items are IDENTICAL because they come from the same ATS analysis.
The Enhancer ADDITIONALLY shows AI-improved content and section editors.


==========================================================
2. USER JOURNEY
==========================================================

Upload Resume (PDF/DOCX)
        |
        v
POST /parser/parse_resume/
  -> resume_id
  -> parsed_data
  -> ats_score (inline, includes SectionBreakdown + Suggestions)
        |
        v
POST /parser/calculate_ats_score/{resume_id}
  -> ats_id          <-- CRITICAL: needed for Enhancer
  -> ats_score       <-- authoritative score for ATS report
        |
        |--------------------------------------+
        v                                      v
  ATS Report Page                     [User clicks "Fix Now"]
  /atslogin/report                             |
  Shows:                                       v
  - Overall score gauge            POST /resume/enhance
  - Section breakdown              { resume_id, ats_breakdown: ats_id }
  - Issues (Critical/Urgent/Optional)          |
  - "Fix Now with AI" button                   v
                                      Enhancer Builder Page
                                      /enhancer/builder
                                      Shows:
                                      - Same ATS score
                                      - Same missing items
                                      - Editable sections (16 sections)
                                      - AI-enhanced content
                                      - Export PDF/DOCX

----------------------------------------------------------
3.1  STEP 1 - Parse Resume
----------------------------------------------------------
POST /api/v1/parser/parse_resume/
Content-Type: multipart/form-data

Body:
  file        : <PDF|DOCX binary>
  template_id : (optional, leave empty)

Response (201):
{
  "resume_id": "69b4e4d84271d6c3e0a2ad48",
  "file_name": "resume.pdf",
  "parsed_data": {
    "contact": { "name": "...", "email": null, "phone": null },
    "llm_data": {
      "experience": [...],
      "education": [...],
      "projects": [...],

    },
    "summary": "...",

7. API CALL SEQUENCE  (Complete Flow)
==========================================================

1.  User uploads file
    -> POST /parser/parse_resume/
    <- resume_id, parsed_data, ats_score (inline, no ats_id)

2.  Calculate ATS score
    -> POST /parser/calculate_ats_score/{resume_id}
    <- ats_id, ats_score (authoritative)

3.  Save to localStorage: atsAnalysisData
    (resume_id + ats_breakdown_id + ats_score + parsed_data)

4.  Redirect to /atslogin/report
    -> Read from localStorage
    -> Display score, breakdown, issues

5.  User clicks "Fix Now"
    -> Read resume_id, ats_breakdown_id from localStorage
    -> Navigate to /enhancer?resume_id=X&ats_breakdown=Y&from_ats=true

6.  Enhancer auto-processes
    -> POST /resume/enhance { resume_id, ats_breakdown }
    <- enhanced_resume_id, enhanced_resume, enhancement_report

7.  Read ats_score from localStorage for display in enhancer
    -> No extra API call needed for score / missing items

8.  Render builder
    -> Display: same ATS score + same missing items + AI-enhanced sections

9.  User edits sections

10. User saves all changes
    -> POST /resume/enhance/{enhanced_id}/bulk-update  (NEW)
    <- updated enhanced_resume

11. User exports
    -> GET /resume/enhance/{enhanced_id}/download?format=pdf&template=X
    <- PDF/DOCX blob

9. BULK UPDATE ENDPOINT - BACKEND IMPLEMENTATION GUIDE
==========================================================

Route:
  POST /api/v1/resume/enhance/{enhanced_id}/bulk-update

What the handler must do:
  1. Find existing enhanced_data document by enhanced_id
  2. For each key in sections{}, deep-merge the value into
     enhanced_data.enhanced_resume
  3. Update template_id if provided
  4. Update updated_at timestamp
  5. Record edited_sections list for audit
  6. Return full updated EnhanceResumeResponse

Validation rules:
  - enhanced_id must exist and belong to the requesting user
  - Only allow known section keys (whitelist validation)
  - PersonalInfo.email must pass format validation
  - Array sections: REPLACE entirely (do not append)

Why a separate endpoint from PATCH:
  PATCH /resume/enhance/{id}  ->  update one or a few fields (single section save)
  POST  /bulk-update          ->  replace all edited sections in one atomic write
                                  (builder "Save All" / pre-export save)

  If the backend already supports full replacement via PATCH, the bulk-update
  endpoint can be a route alias pointing to the same handler.
