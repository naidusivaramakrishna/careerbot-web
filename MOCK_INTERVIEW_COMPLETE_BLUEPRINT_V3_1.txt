================================================================================
1.1  SYSTEM PHILOSOPHY
================================================================================

WHO IS THE USER:
  - Indian, age 20-25, fresher (0-3 years experience)
  - Can READ English, struggles to SPEAK it confidently in interviews
  - Knows the answer in Hindi/regional language, can't express in English
  - Goal: clear ONE interview THIS WEEK, not learn English over months

WHAT THIS SYSTEM DOES:
  PREPARATION SYSTEM (record-and-evaluate, Weeks 1-2):
    1. Parse resume -> generate NOTES of what to say (self-intro, projects, HR)
    2. Show 30 INTERVIEW PHRASES (not grammar, not vocabulary)
    3. PRACTICE: record answer -> get transcript -> get feedback -> repeat
    4. READINESS GATE: must score avg 6/10 before entering mock

  LIVE AI MOCK INTERVIEW (real-time AI conversation, Week 3):
    5. AI SPEAKS the question via Azure Neural TTS
    6. Candidate SPEAKS the answer (streamed to Azure STT)
    7. AI gets transcript in real-time -> chooses next question via LLM
    8. Report generated at end with all scores

CORE RULE: "Don't teach English. Teach INTERVIEW English."

================================================================================
1.2  TWO-SYSTEM DESIGN
================================================================================

SYSTEM A - PREPARATION (Record-and-Evaluate):
  Used for: Notes generation, HR practice, Technical practice
  Audio path: Browser records .webm -> POST to Backend -> ffmpeg -> Whisper -> LLM
  Latency:   5-10 seconds per answer (acceptable for practice)
  Cost:      ~$0.003-0.005 per answer

SYSTEM B - LIVE AI INTERVIEW (Real-Time Conversation):
  Used for: Mock HR Interview, Mock Technical Interview
  Audio path: Browser streams raw PCM chunks -> WebSocket -> Azure STT (streaming)
              Azure STT transcript -> Llama-3.3-70B -> decision -> Azure TTS -> Browser
  Latency:   Per-component (NOT end-to-end):
               STT final transcript: <1.5s after candidate stops speaking (silence detected)
               LLM decision (P6_LIVE): 1-3s (150 tokens, fast path)
               TTS generation: <1.5s for 30-word question
               End-to-end (silence detected -> AI question audio plays): 4-8 seconds
             Note: "4-8 seconds" is the realistic UX expectation. This is acceptable for
             a live AI interview (human interviewers also take 3-5 seconds to respond).
  Cost:      ~$0.004-0.006 per question exchange

WHY TWO SYSTEMS:
  - Practice mode needs DETAILED feedback (requires full transcript first)
  - Mock interview needs REALISM (AI must feel like a human interviewer)
  - Different latency requirements, different audio pipelines

1.4  PREPARATION SYSTEM FLOW (Practice Mode)
================================================================================

USER:  Speaks answer (max 2 min)
         |
         | Browser: MediaRecorder -> .webm blob
         v
FRONTEND: POST /mock-interview/practice/answer
          FormData: { audio: .webm, session_id, question_id }
         |
         v
BACKEND:  1. Validate audio (file_security.py, max 10MB)
          2. Save .webm to /tmp/{uuid}.webm
          3. ffmpeg -i input.webm -ar 16000 -ac 1 output.mp3  (server-side)
          4. DELETE original .webm immediately
          5. Call AI Layer: POST /api/v1/audio/to-text
         |
         v
AI LAYER: Whisper transcribes mp3 -> returns transcript (free, local)
         |
         v
BACKEND:  6. DELETE mp3 after transcript received
          7. rule_checker.check(transcript, question)
             -> filler_count, key_points_hit, length_seconds
          8. IF weighted_rule_score >= 7: SKIP LLM (save cost)
             ELSE: Call AI Layer: LLM feedback (P5 / P10)
          9. Save answer + score to MongoDB
          10. Update Redis session state
         |
         v
FRONTEND: Display: transcript + score (0-10) + feedback + improved_answer
          Buttons: [Try Again] [Next Question]

KEY DECISION: ffmpeg runs IN BACKEND, not in browser.
              Browser sends raw .webm. Backend converts. Never trust browser conversion.

================================================================================
1.5  LIVE AI INTERVIEW FLOW (WebSocket)
================================================================================

  STEP 1: SETUP
  Frontend: Opens WebSocket -> WS /mock-interview/live/{session_id}
  Backend:  Validates JWT from query param
  Backend:  Creates live session in Redis: mock:live:{session_id}:state
  Backend:  Selects 8-10 questions from question bank (P6 logic)
  Backend:  Generates FIRST QUESTION audio via Azure TTS
  Backend:  Sends to Frontend: {type: "question_audio", data: base64_audio}
  Frontend: Plays audio via AudioContext (Web Audio API)

  STEP 2: PER-QUESTION LOOP
  +--> Frontend:  User speaks -> MediaRecorder captures PCM chunks
  |    Frontend:  Every 250ms: send {type: "audio_chunk", data: base64_pcm}
  |    Backend:   Buffers chunks -> streams to Azure STT
  |    Azure STT: Returns partial transcripts -> Backend sends {type: "transcript_partial"}
  |    Frontend:  Shows live "You said: ..." caption
  |
  |    User stops (VAD detects silence > 1.5s):
  |    Frontend:  sends {type: "end_answer"}
  |    Azure STT: Returns final transcript
  |    Backend:   1. Rule check (filler count, length < 10s = too short)
  |               2. LLM: Should we ask a follow-up OR move to next Q? (P6-live)
  |               3. If follow-up: generate follow-up question -> Azure TTS -> send
  |               4. If next: evaluate answer via LLM (P7-live) -> store score
  |               5. Select next question -> Azure TTS -> send
  +--> Backend: sends {type: "question_audio"} -> loop repeats

  STEP 3: COMPLETION
  After all questions answered (or user sends {type: "end_interview"}):
  Backend:  Run P8 prompt with all answers -> generate report
  Backend:  Save report to MongoDB
  Backend:  Send {type: "interview_complete", report: {...}}
  Frontend: Navigate to /report?session={session_id}
  Backend:  Close WebSocket connection

PART 5: WEBSOCKET PROTOCOL (Live AI Interview)
################################################################################

================================================================================
5.1  CONNECTION LIFECYCLE
================================================================================

  1. Frontend opens:   WS ws://api:8000/mock-interview/live/{session_id}?token={jwt}
  2. Backend:          Validates JWT. Additional checks before accept():
                         a) JWT must NOT expire within the next 30 minutes.
                            If token expires soon: close(4003, "Token expiring. Please re-login.")
                            Reason: A live mock session can run 25+ minutes. Token must last.
                         b) session_id must belong to the authenticated user (not someone else's).
                         c) session must exist in Redis and status != "DONE".
                         d) User must not already have 3 active WS connections.
  3. Backend:          Loads session from Redis. Generates/sends FIRST question audio.
  4. Per-question:     Loop (see 5.4 state machine)
  5. Completion:       Backend sends interview_complete message. Frontend closes WS.
  6. Timeout:          If no message for 60s, Backend sends keepalive ping.
  7. Hard limit:       After 45 minutes of session age, Backend sends SESSION_EXPIRED error
                       and closes WS gracefully (saves partial results first).
  8. Disconnect:       On disconnect, session saved to Redis. User can reconnect within 3h.
  9. Reconnect:        Frontend reopens WS with same session_id + reconnect_token (see 5.4).
                       Backend verifies reconnect_token before resuming session.

  STREAMING RATE LIMIT:
    Max inbound audio_chunk messages: 50KB/s sustained (burst: 200KB)
    If client sends audio faster than 50KB/s: drop excess chunks, DO NOT disconnect.
    Reason: Prevents DoS via rapid audio_chunk flooding. Normal PCM at 16000Hz/16-bit
    = 32KB/s, so 50KB/s limit is generous for normal use but blocks abuse.

================================================================================
5.2  CLIENT -> SERVER MESSAGES
================================================================================

  { "type": "audio_chunk",  "data": "<base64_pcm_16000hz_mono>", "seq": 1 }
  { "type": "end_answer",   "session_id": "<id>" }
  { "type": "end_interview","session_id": "<id>" }
  { "type": "ping" }

  AUDIO FORMAT for streaming:
    Format: PCM 16-bit, 16000Hz, mono (required by Azure STT)
    Chunk size: ~4096 bytes every 128ms (or .webm chunks every 250ms)
    Frontend converts via: audioWorklet OR AudioContext.createScriptProcessor

  AUDIO BUFFER LIMITS (Backend enforces):
    Max audio_buffer size per answer: 5MB (= ~156 seconds of PCM at 32KB/s)
    If buffer exceeds 5MB before end_answer: treat as end_answer (auto-stop).
    Reason: Prevents unbounded memory usage if client never sends end_answer.
    Per-session max audio: 50MB total across all answers.
    If session total exceeds 50MB: send SESSION_EXPIRED error and close.

  SEQUENCE NUMBER HANDLING:
    seq field on audio_chunk is informational (for client-side debugging).
    Backend does NOT reorder based on seq. Chunks are appended in receive order.
    If out-of-order chunks arrive (network reorder), Azure STT handles gracefully.

================================================================================
5.3  SERVER -> CLIENT MESSAGES
================================================================================

  { "type": "session_ready",     "question_count": 9, "time_limit_per_q": 120 }
  { "type": "question_audio",    "data": "<base64_mp3>", "question_text": "...", "question_num": 1 }
  { "type": "transcript_partial","text": "I am a...", "seq": 5 }
  { "type": "transcript_final",  "text": "I am a software developer...", "duration_s": 45 }
  { "type": "follow_up",         "data": "<base64_mp3>", "follow_up_text": "Can you elaborate?"}
  { "type": "answer_scored",     "question_num": 1, "weighted_score": 7.2 }
  { "type": "interview_complete","report": { ...full report object... } }
  { "type": "error",             "code": "STT_FAILED", "message": "...", "recoverable": true }
  { "type": "pong" }

================================================================================
5.4  STATE MACHINE (per live session)
================================================================================

  States: INIT -> QUESTION_PLAYING -> LISTENING -> PROCESSING -> DONE
                                                       |
                                               (FOLLOW_UP -> LISTENING)

  INIT:             Session loaded, first question TTS generated
  QUESTION_PLAYING: Audio being played by Frontend (no audio received)
  LISTENING:        Receiving audio chunks, streaming to Azure STT
  PROCESSING:       End_answer received, evaluating response, generating next Q
  DONE:             All questions complete, report generated

  RECOVERY: If client disconnects in LISTENING or PROCESSING:
    - Save current question index to Redis (TTL=3h)
    - Generate a short-lived reconnect_token: secrets.token_urlsafe(16), TTL=5 minutes
    - Store in Redis: mock:reconnect:{session_id} = reconnect_token  TTL=300s
    - Return reconnect_token to client in the LAST WS message before close:
        { "type": "session_paused", "reconnect_token": "xyz123...", "resume_at_q": 3 }
    - On reconnect: Frontend passes both session_id AND reconnect_token in query:
        WS ?token={jwt}&reconnect_token={reconnect_token}
    - Backend verifies: reconnect_token must match Redis value AND not be expired
      If valid: resume from saved question index (TTL resets to 3h)
      If invalid/expired: close(4005, "Reconnect token invalid. Start new session.")
    - Why: Prevents attacker who knows session_id from hijacking another user's session.

================================================================================
5.5  ERROR HANDLING IN WEBSOCKET
================================================================================

  ERROR CODE         | RECOVERABLE | ACTION
  STT_FAILED         | Yes         | Ask user to repeat ("Sorry, I didn't catch that")
  STT_SDK_ERROR      | Yes (2x)    | Restart Azure STT recognizer in-session (see below)
  TTS_FAILED         | Yes         | Send question as text + show typed question on screen
  LLM_TIMEOUT        | Yes         | Use rule-based next question selection (no LLM)
  AUDIO_TOO_SHORT    | Yes         | Ask user to give a longer answer (< 5 seconds)
  AUDIO_BUFFER_FULL  | Yes         | Auto-trigger end_answer, process what was received
  SESSION_EXPIRED    | No          | Redirect to create new session
  AUTH_FAILED        | No          | Redirect to login
  RECONNECT_INVALID  | No          | Redirect to create new session

  GRACEFUL DEGRADATION:
    If Azure STT is down:     Fall back to Whisper (collect full audio, transcribe after answer)
    If Azure TTS is down:     Show question text on screen, user reads and speaks
    If LLM is down:           Select next question using rule-based rotation from question bank

  STT SDK RECONNECT STRATEGY (FIX-6):
    Problem: Azure SpeechRecognizer SDK connection can drop mid-answer even if Azure service
             is healthy (network blip, timeout). Unlike "Azure STT is down", this is transient.
    Detection: recognizer.canceled event fires with CancellationReason.Error
    Strategy: Restart the recognizer within the SAME WebSocket session (max 2 retries/answer):

    In speech_client.py transcribe_stream():
      canceled_event = asyncio.Event()
      retry_count = 0

      def on_canceled(e):
          if e.result.cancellation_details.reason == CancellationReason.Error:
              canceled_event.set()  # Signal to retry

      recognizer.canceled.connect(on_canceled)
      recognizer.start_continuous_recognition_async()

      # ... chunk feeding loop ...

      # After push_stream.close():
      recognizer.stop_continuous_recognition_async()
      if canceled_event.is_set() and retry_count < 2:
          retry_count += 1
          # Re-create recognizer with same push_stream data
          # (caller must buffer audio chunks for retry)
          # Signal backend to retry, NOT to close WebSocket

    Retry limit: 2 retries per answer. If still failing after 2: fall back to Whisper.
    Note: Audio chunks must be buffered in handle_end_answer for retry to work.

  STREAMING ABUSE PROTECTION:
    Max audio_chunk messages per second: 20 (normal PCM at 128ms = ~8/sec)
    If client sends > 20 audio_chunks/second: drop excess, DO NOT disconnect.
    This blocks audio flooding attacks while preserving normal audio quality.

DAY 6: AUDIO PIPELINE (Server-Side Conversion)
  rule_checker.py:
    FILLER_WORDS = ["umm", "uhh", "basically", "you know", "actually", "like"]
    def check(transcript: str, question: dict, duration_s: float) -> dict:
      filler_count = sum(t.lower().split().count(f) for f in FILLER_WORDS)
      key_points_hit = [kp for kp in question["key_points"]
                        if any(w in transcript.lower() for w in kp.lower().split())]
      length_ok = MIN_AUDIO_DURATION_S <= duration_s <= MAX_AUDIO_DURATION_S
      # Rule-based weighted score (0-10)
      content_rule = min(10, len(key_points_hit) * 2.5)
      clarity_rule = max(0, 10 - filler_count * 1.5)
      length_rule = 10 if length_ok else (5 if duration_s < MIN_AUDIO_DURATION_S else 7)
      rule_score = content_rule * 0.4 + clarity_rule * 0.4 + length_rule * 0.2
      return { "filler_count", "key_points_hit", "length_ok", "rule_score" }

  service.py -> submit_practice_answer():
    async def submit_practice_answer(session_id, question_id, audio_file, user_id):
      # 1. Validate file
      file_security.validate(audio_file, allowed_types=[".webm"], max_mb=10)

      # 2. Server-side conversion
      input_path = f"/tmp/{uuid4()}.webm"
      mp3_path = f"/tmp/{uuid4()}.mp3"
      try:
          with open(input_path, "wb") as f: f.write(await audio_file.read())
          process = await asyncio.create_subprocess_exec(
              "ffmpeg", "-i", input_path, "-ar", "16000", "-ac", "1", mp3_path,
              stdout=asyncio.subprocess.PIPE, stderr=asyncio.subprocess.PIPE
          )
          await asyncio.wait_for(process.communicate(), timeout=30.0)
          if process.returncode != 0: raise AudioConversionError("ffmpeg failed")
      finally:
          if os.path.exists(input_path): os.unlink(input_path)

      # 3. Transcribe (AI Layer Whisper)
      try:
          transcript_resp = await asyncio.wait_for(
              ai_client.post("/api/v1/audio/to-text", files={"audio": open(mp3_path,"rb")}),
              timeout=20.0
          )
      finally:
          if os.path.exists(mp3_path): os.unlink(mp3_path)
      transcript = transcript_resp["transcript"]
      duration_s  = transcript_resp["duration_seconds"]

      # 4. Rule check
      question = await repository.get_question(question_id)
      rule = rule_checker.check(transcript, question, duration_s)

      # 5. LLM feedback (only if rule score < threshold)
      llm_scores, feedback, improved = None, None, None
      if rule["rule_score"] < LLM_SCORE_THRESHOLD:
          llm_result = await asyncio.wait_for(
              ai_client.post("/api/v1/mock-interview/practice-feedback",
                             json={"transcript": transcript, "question": question,
                                   "rule_scores": rule}),
              timeout=20.0
          )
          llm_scores = llm_result["scores"]
          feedback   = llm_result["feedback"]
          improved   = llm_result["improved_answer"]
      else:
          llm_scores = _rule_to_llm_scores(rule)

      # 6. Save to MongoDB + update Redis session
      await repository.save_answer(session_id, question_id, transcript,
                                   duration_s, rule, llm_scores, feedback, improved)
      await redis.set_session_state(session_id, question_id)
      return PracticeAnswerResponse(...)

      async def transcribe_stream(audio_generator) -> AsyncIterator[str]:
        """Stream PCM audio chunks through Azure STT. Yield partial + final transcripts."""
        push_stream = speechsdk.audio.PushAudioInputStream()
        audio_config = speechsdk.audio.AudioConfig(stream=push_stream)
        recognizer = speechsdk.SpeechRecognizer(
            speech_config=self.speech_config, audio_config=audio_config
        )
        queue = asyncio.Queue()
        recognizer.recognizing.connect(lambda e: queue.put_nowait(("partial", e.result.text)))
        recognizer.recognized.connect(lambda e: queue.put_nowait(("final", e.result.text)))
        recognizer.start_continuous_recognition_async()
        async for chunk in audio_generator:
            push_stream.write(chunk)
        push_stream.close()
        recognizer.stop_continuous_recognition_async()
        while not queue.empty():
            yield await queue.get()

    async def live_interview_ws(websocket: WebSocket, session_id: str, token: str):
      # Authenticate
      user = await get_user_from_token(token)
      if not user: await websocket.close(4001, "Unauthorized"); return

      # Load session from Redis
      session = await redis.get(f"mock:live:{session_id}:state")
      if not session: await websocket.close(4004, "Session not found"); return

      await websocket.accept()

      # Send first question audio
      first_q_audio = await tts_client.text_to_speech(session["questions"][0]["question_text"])
      await websocket.send_json({
          "type": "question_audio",
          "data": base64.b64encode(first_q_audio).decode(),
          "question_text": session["questions"][0]["question_text"],
          "question_num": 1
      })

      # Main receive loop
      audio_buffer = []
      try:
          while True:
              data = await asyncio.wait_for(websocket.receive_json(), timeout=120.0)
              if data["type"] == "audio_chunk":
                  audio_buffer.append(base64.b64decode(data["data"]))
              elif data["type"] == "end_answer":
                  await handle_end_answer(websocket, session, audio_buffer, session_id)
                  audio_buffer = []
              elif data["type"] == "end_interview":
                  await finalize_interview(websocket, session, session_id, user)
                  break
              elif data["type"] == "ping":
                  await websocket.send_json({"type": "pong"})
      except asyncio.TimeoutError:
          await websocket.send_json({"type": "error", "code": "TIMEOUT",
                                     "message": "No activity for 120s"})
      except WebSocketDisconnect:
          # Save state to Redis for reconnection
          await redis.setex(f"mock:live:{session_id}:state", 10800, json.dumps(session))

  handle_end_answer(websocket, session, audio_buffer, session_id):
    1. Stream audio_buffer to Azure STT -> get final transcript
       (send partial transcripts back to client as they arrive)
    2. Rule check: if len(transcript) < 10: ask to repeat
    3. Update conversation history in Redis
    4. Call Llama (P6-live): should follow-up OR move to next question?
       - If follow-up: TTS follow-up question -> send question_audio
       - If next: score current answer (P7-live) -> select next question -> TTS -> send
    5. Update session state (current_index, history) in Redis

    class AudioProcessor extends AudioWorkletProcessor {
      process(inputs) {
        const input = inputs[0][0];  // Float32 PCM
        const pcm16 = new Int16Array(input.length);
        for (let i = 0; i < input.length; i++) {
          pcm16[i] = Math.max(-32768, Math.min(32767, input[i] * 32768));
        }
        this.port.postMessage({ type: "chunk", pcm: pcm16.buffer }, [pcm16.buffer]);
        return true;
      }
    }
    registerProcessor("audio-processor", AudioProcessor);

         Max 1 follow-up per question. If remaining questions < 3: never follow-up.
  Output JSON: { action: "follow_up" | "next_question",
                  follow_up_text: null | "Can you tell me more about..." }

################################################################################
PART 9: SCORING ARCHITECTURE
################################################################################

PRACTICE SCORE (per answer, 0-10):
  Dimension     Weight  Source
  Content       40%     Key points from question bank matched in transcript
  Clarity       30%     Filler word count, sentence coherence (LLM)
  Structure     20%     Beginning/middle/end flow (LLM)
  Length        10%     Duration within 30-120 seconds

  Rule-based fast path (no LLM):
    content_rule = min(10, len(key_points_hit) * 2.5)
    clarity_rule = max(0, 10 - filler_count * 1.5)
    length_rule  = 10 if 30 <= duration <= 120 else 5
    rule_score   = content_rule*0.4 + clarity_rule*0.4 + length_rule*0.2
    IF rule_score >= 7.0: skip LLM, return rule_score as final

  LLM path (when rule_score < 7):
    P5 or P10 returns all 4 dimension scores
    weighted_score = content*0.4 + clarity*0.3 + structure*0.2 + length*0.1

  Technical (V2): adds technical_accuracy (0-10) at 30% weight
    New weights: content*0.25 + clarity*0.25 + structure*0.2 + length*0.1 + tech_acc*0.3*10

MOCK SCORE (same dimensions + pressure_tag):
  pressure_tag = "pressure_affected" if mock_score < practice_avg - 3
  pressure_tag = "handles_pressure_well" if mock_score >= practice_avg

VIDEO SCORE (V2, per question):
  eye_contact_score = eye_contact_ratio * 10
  focus_score       = focus_ratio * 10
  emotion_score     = confidence_from_emotion_distribution(emotion_dist)
  video_score       = eye_contact*0.3 + focus*0.3 + emotion*0.2 + confidence*0.2

OVERALL REPORT SCORE:
  V1 (HR only):  hr_readiness*0.5 + communication*0.3 + confidence*0.2
  V2 (with Tech): hr*0.35 + technical*0.30 + communication*0.25 + video*0.10

CALIBRATION ADJUSTMENT:
  calibrated_score[dim] = raw_score[dim] + profile[dim + "_adjustment"]
  Bounds: max(0, min(10, calibrated_score))
  Applied when: profile.sample_count >= 20 AND profile.correlation >= 0.6
